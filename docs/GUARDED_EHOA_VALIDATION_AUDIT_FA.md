# ممیزی جامع Guarded EHOA

تاریخ ممیزی: 2026-08-18

## نتیجه‌ی اجرایی

| محور | وضعیت | شاهد |
|---|---|---|
| صحت نحوی کل پروژه | تأیید | `python -m compileall -q .` |
| آزمون‌های خودکار | تأیید | 25 آزمون پاس شد |
| کیفیت patch | تأیید | `git diff --check` بدون خطا؛ فقط هشدار LF/CRLF |
| نبود outer-test leakage | تأیید کدی | runner فقط `Xtr,ytr` را به selector می‌دهد؛ guard فقط foldهای ساخته‌شده از همان ورودی را می‌خواند |
| جدایی preprocessing | تأیید | imputer، scaler و SMOTE فقط روی بخش train هر fold fit می‌شوند |
| تکرارپذیری | تأیید | بازاجرای مستقل 60 اجرا؛ 24 ستون deterministic با تحمل `1e-12` کاملاً یکسان |
| یکتایی اجراها | تأیید | 60 کلید یکتا و صفر گروه تکراری |
| برابری بودجه‌ی جست‌وجو | تأیید | میانگین evaluationهای EHOA و G-EHOA در هر دیتاست برابر است |
| بهبود میانگین بیرونی | تأیید مشاهده‌ای | در هر دو دیتاست مثبت است |
| برتری آماری | رد | Wilcoxon و Holm در سطح 0.05 معنادار نیستند |
| novelty مطلق جهانی | تأییدنشده | wrapper-CV و مقایسه با full set در ادبیات سابقه دارند؛ مرور نظام‌مند لازم است |
| کفایت برای مقاله‌ی نهایی | مشروط | برای ادعای کاهش ریسک مشاهده‌شده مناسب؛ برای ادعای برتری قطعی یا novelty بی‌سابقه ناکافی |

## بازتولید مستقل

اجرای دوم با `configs/guarded_repro_check.yaml` از صفر انجام شد. کلیدهای dataset، method، seed و fold یکسان بودند. ستون‌های subset، fitness، evaluation count، همه‌ی معیارهای طبقه‌بندی، redundancy، interaction quality و پایداری در تمام سطرها دقیقاً بازتولید شدند. زمان و حافظه از مقایسه‌ی برابری حذف شدند، زیرا ذاتاً به وضعیت سیستم وابسته‌اند.

## حکم نهایی

پیاده‌سازی، leakage-safety، تکرارپذیری، برابری بودجه و افزایش میانگین بیرونی تأیید می‌شوند. «بهبود آماری قطعی»، «تعمیم به داده‌های پُربُعد» و «نوآوری جهانی بی‌سابقه» تأیید نمی‌شوند. مقاله باید این سه محدودیت را صریح نگه دارد و برای عبور از آن‌ها از دیتاست‌های مستقل بیشتر استفاده کند؛ افزایش گزینشی seed روی همین دو دیتاست جایگزین معتبری نیست.
